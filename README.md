# Flux —— 瓶颈管理微信小程序

基于**约束理论（TOC）+ 利特尔法则 + 关键路径法（CPM）**的任务管理小程序：帮你从一堆待办中找出**当前唯一卡点**，AI 多层级拆解成可立即执行的小任务，并结合个人知识库给出针对性建议。

技术栈：微信小程序原生开发（WXML + WXSS + JS）+ 微信云开发 CloudBase（云函数 + 云数据库 + 云存储 + AI+ 大模型服务）。

---

## 一、核心功能

### 1. 首页 · 瓶颈仪表盘（`pages/index`）

- **瓶颈识别**：多个未完成大目标时，自动锁定"预计耗时最长"者为唯一焦点目标（in_progress），其余锁定（locked），锁定目标的全部层级后代同步锁定，避免多线程切换
- **多层级任务树**：目标支持 1~5 层动态拆解（每节点最多 8 个子任务，全树 ≤40 节点），缩进列表渲染、展开/折叠、逐层瓶颈高亮
- **卡点链**：每层跑 CPM 关键路径，逐层向下追踪，最深层瓶颈即"现在立刻该做的事"（红色高亮）；树超过 4 层默认展开到第 3 层
- **完成联动**：叶子完成后，"全部子任务已完成"的各级祖先逐层自动完成（含破裂动画）；恢复未完成沿祖先链逆转
- **在办警告**：在办计数只统计大目标（10 个子任务只算 1 个），>3 个大目标才触发警告
- **专注计时**：瓶颈目标自动累计专注时长，定期落库；删除任意目标前先结算未落库增量，不会因瓶颈切换而丢失
- **数据边界收敛**：`api.normalize` 是页面唯一数据入口，对 `dependencies`/`actualHours`/`estimatedHours`/`level`/`userContext.tags` 等做**类型收敛**（非数组→`[]`、非有限数值→`0`）。历史版本、云控制台手改、外部导入写进的类型脏字段不会再把整页渲染搞崩
- **失败不锁死**：所有写操作（添加/完成/删除/补充提交）均为 try/catch/finally，`submitting` 无条件复位 —— 任何内部异常都不会让首页变成只读

### 2. 拆解页 · 多目标批量 AI 拆解（`pages/breakdown`）

- **一句话输入多目标**：自然语言一次性粘贴多个目标（如"做实验、写周报、准备季度汇报PPT"），AI 自动识别目标列表、按依赖关系合并/拆分、给出建议拆解深度
- **目标确认**：识别结果可编辑（改标题/备注/复杂度）后再拆解
- **串行逐个拆解**：遵守 AI 串行队列约束逐个拆解，卡片增量渲染（无需等全部完成），每卡片显示"正在拆解/排队等待"状态与已完成计数
- **批量性能保障**：两级时间预算（单目标 35s / 整批 90s）+ AI 熔断冷却 + 云函数失败跳过，任何通道异常下批量循环必然收敛，不会永久卡在"正在拆解"
- **对话式调优**：对拆解初稿用自然语言反馈（"步骤太多了""并行安排"），AI 重新生成任务树；支持从首页载入已有目标进入调优
- **逐个/全部采纳**：可单卡片采纳，也可全部采纳（串行 + 共享去重映射），采纳即写入云数据库

### 3. 智能建议（Agent 行动层，`utils/suggestions` + `utils/ai`）

- **规则引擎兜底**：永远可用的本地建议（超时 1.5 倍 → 前置未完成 → 阻塞 ≥3 下游 → 就绪未开始 → 整体偏慢）
- **AI 增强**：全局瓶颈目标的卡点额外用大模型生成 1~2 条建议（30 分钟缓存，失败静默回退规则建议，5 分钟失败冷却防重试风暴）
- **建议交互**：采纳（按类型自动处理，如跳转拆解页）/ 忽略 / 反馈有用·没帮助
- **补充情况 → 重新生成**：觉得建议不具体？就地补充"缺资源/不会做/试过没用…"等快速标签 + 文字描述，Agent 结合知识库重新生成针对性建议（三层降级：客户端 AI → 云函数 refineSuggestion → 标签规则）
- **建议历史**：补充与建议历史存 `tasks.userContext/suggestionHistory`，刷新不丢失

### 4. 知识库 · Agent 长期记忆（`pages/knowledge`）

- **双来源**：项目管理理论（内置）+ 个人经验（用户沉淀）
- **自动提取**：有价值的用户补充自动提取进知识库待确认区，确认后转为个人经验
- **知识检索**：生成建议时自动检索匹配知识（子串双向包含打分，个人经验优先，top 3），命中知识 `usageCount + 1`
- **越用越懂你**：个人经验持续累积，建议针对性越来越强

### 5. 波动预警 · 牛鞭效应检测（`pages/fluctuation`）

- **变更留痕**：修改"有业务含义"的字段（标题/描述/预估工时/依赖/项目）会累计 `modificationCount`，并追加一条变更明细 `changeLog`（`{ts, field, from, to}`，环形缓冲最近 20 条）
- **干净数据**：状态流转（pending→locked→in_progress→completed）与系统自动行为（依赖回填、重新排期）**不计入**修改次数，也不写明细
- **四类风险**，每条给出结构化证据 + 中文解释 + 可执行建议：
  - `unstable_root` **需求源头反复变更** —— 大目标自身高频修改，此时下游任何排期都会被推翻
  - `amplified` **计划被放大** —— 上游相对稳定、本层反复重写（放大比 = 本层变更次数 / 需求源头变更次数，牛鞭效应的本体）
  - `burst` **近期集中变更** —— 7 天内集中多次修改，需求处于动荡期，不宜继续投入
  - `estimate_churn` **工时估算反复调整** —— 工作量还没估准（附调整次数与幅度）
- **定位视图**：按层级聚合"变更集中在哪一层" + 变更最多的节点排行 + 按大目标聚合（子树规模 / 累计变更 / 变更热区）
- **一键重新排期**：按「父节点耗时 = 直接子任务合计」不变式自底向上重算目标子树，先列出修正项与各层关键路径，用户确认后一次性写库（系统行为，不计入修改次数）
- **纯本地计算**：算法在 `utils/fluctuation.js`（无 wx / 无 IO / 无网络依赖），离线可用、毫秒级、可完整单测；阈值可配置，默认取保守值（宁可少报，不制造焦虑）

## 二、AI 架构

### 模型配置（`miniprogram/utils/ai.js`）

按优先级依次降级尝试（任一成功即返回）：

| 优先级 | Provider | Model | 说明 |
|---|---|---|---|
| 1 | `hunyuan-v3` | `hy3` | 小程序成长计划免费额度通道（兼容低版本基础库） |
| 2 | `cloudbase` | `hy3` | 官方推荐标准通道（需基础库 ≥ 3.15.1） |
| 3 | `cloudbase` | `deepseek-v4-flash` | 付费兜底 |

每个模型入口内：**streamText 优先**（免费通道下流式更稳定），generateText 兜底。

### 可靠性机制

- **全局串行队列**：同一时刻仅一个 AI 请求在途，防并发 429
- **429 退避重试**：1.5s → 3s 递增，最多 2 次
- **硬超时**：单次流式 25s / 非流式 15s（`withTimeout`，败者定时器已清理防未处理拒绝）
- **时间预算**：单次调用可传 `budgetMs`，预算精确中断在途请求（批量拆解单目标 35s / 整批 90s / parseGoals 60s）
- **熔断冷却**：全部入口失败后快速失败——一般错误 60s / 额度类错误 5min / 预算耗尽 30s，冷却期后续目标直接预设降级，自动恢复

### 三层降级调用链（以拆解为例）

```
层1 客户端直调 wx.cloud.extend.AI（ai.js breakdownGoal）
  ↓ 失败
层2 云函数 breakdownTask（服务端同款模型链 + 内部预设降级，25s 总预算）
  ↓ 失败
层3 预设任务树 + 预设信息缺口（永远有结果）
```

目标识别（parseGoals）、建议重生成（refineSuggestion）、知识提取（extractKnowledge）均为同构三层降级，**任何网络/额度/通道异常下功能不会中断**。

## 三、数据层设计

### 云数据库集合

| 集合 | 用途 | 建议索引 |
|---|---|---|
| `tasks` | 全部任务（level 0 大目标 + level 1..N 子任务，parentGoalId 指向直接父节点） | `createdAt` 升序；`parentGoalId+status` |
| `projects` | 项目（预留） | — |
| `knowledge` | 知识库（理论 + 个人经验 + 待确认区） | `createdAt`；`status+type` |
| `op_logs` | 操作日志（云端批量上报） | `_openid+createdAt` |

数据安全规则：所有集合**仅创建者可读写**（`auth.openid == resource.openid`）。

### 数据可靠性（`miniprogram/utils/`）

| 模块 | 职责 |
|---|---|
| `validation.js` | 写库前 Schema 校验（类型/必填/枚举/长度截断），中文错误提示 |
| `crypto.js` | 敏感字段加密（`userContext.text`，XXTEA-128 + 设备本地密钥，`enc1:` 前缀，读取透明解密，兼容存量明文） |
| `dberrors.js` | 错误分类（network/permission/validation/notfound/collection/limit/unknown）+ 友好提示 + 幂等读自动重试（1 次，1s 退避） |
| `oplog.js` | 操作日志：本地环形缓冲（200 条）→ 批量上报云端（20 条阈值 / 60s 间隔），离线不丢 |
| `api.js` | 数据访问层：校验 + 加密 + 日志 + 重试统一收口，云端优先、本地兜底 |

### 前端算法（均为毫秒级，<20 任务规模）

- `cpm.js`：关键路径法（同层依赖关系）
- `tree.js`：树归一化 / DB 树构建 / CPM 标注 / 卡点链 / 扁平化渲染 / 递归导入 / 差异同步 / 完成联动 / 规则调优
- `fluctuation.js`：需求波动 / 牛鞭效应检测（森林构建兜底环与悬挂引用 → 四类风险判定 → 目标/层级/子树聚合）+ 重新排期方案（纯计算，不写库）

## 六、部署步骤

1. **开通环境**：微信开发者工具 → 云开发控制台 → 开通环境；「AI+」中启用 `hy3`（及可选 `deepseek-v4-flash`）
2. **初始化集合**：右键 `cloudfunctions/initDatabase` →「上传并部署：云端安装依赖」→ 调用一次，按返回的 `indexSpecs` 建索引、按 `securityRules`（仅创建者可读写）设置各集合安全规则
3. **部署全部云函数**：对 `parseGoals`、`breakdownTask`、`refineTask`、`refineSuggestion`、`extractKnowledge`、`analyzeBottleneck`、`checkMultiTasking` 逐个右键 →「上传并部署：云端安装依赖」
4. **编译小程序**：基础库版本设置 ≥ 3.7.1（AI 能力要求）

## 七、关键约束与性能指标

- 基础库 ≥ 3.7.1（`wx.cloud.extend.AI` 最低要求；`cloudbase` 供应商需 ≥ 3.15.1，低版本自动走 hunyuan-v3 入口）
- 首页加载 < 1.5 秒（瓶颈/在办检测在页面本地计算，不等云函数）
- AI 调用均有 loading 态防重复点击；AI 失败必有降级方案（规则建议/预设树/手动输入）
- AI 串行队列：同一时刻仅一个请求在途；429 退避 1.5s→3s，最多 2 次
- 任务树 ≤5 层、每节点 ≤8 子任务、全树 ≤40 节点
- 状态流转不计入 modificationCount（牛鞭效应检测需要干净数据）
- 变更明细 `changeLog` 环形缓冲上限 20 条；达到上限时页面显式提示"计数为下界"
- 波动判定阈值（可在 `utils/fluctuation.js` 的 `DEFAULTS` 调整）：变更 ≥3 次且达源头 3 倍 → 放大；7 天内 ≥4 次 → 集中变更；工时调整 ≥2 次 → 估算不稳；大目标自身 ≥4 次 → 源头不稳
- 波动检测为纯本地计算，不依赖云函数（离线可用，无额外网络失败面）

## 八、测试

零依赖 Node 原生测试（`node --test`，无需安装任何包），覆盖 utils 纯逻辑、页面逻辑、云函数：

```bash
node --test "tests/**/*.test.js"
```

- `tests/helpers/runtime.js`：小程序运行时替身（内存 Storage / `wx` / `Page` / `wx-server-sdk` / 云数据库），支持 `setData` 数据路径语法与模块级状态隔离
- `tests/unit/`：`api` / `tree` / `cpm` / `suggestions` / `fluctuation` / `validation` / `knowledge` 等纯逻辑
- `tests/pages/index.test.js`：首页展开状态跨刷新保留（单点回归）
- `tests/pages/index-scenarios.test.js`：**瓶颈首页典型使用场景**，按三类铺开 ——
  - **正常路径**：多目标锁定与切换、任务树完成联动与逆转、添加/删除目标、补充情况重新生成建议、建议采纳/忽略、多任务警告、跨页面数据一致性收敛
  - **边界条件**：只有 1 个/恰好 3 个/4 个大目标、子任务不计入在办、耗时相同时的瓶颈选取、标题与耗时取值边界（空白/0/负数/非数字/超上限）、标签上限 3 个、描述截断 200 字、进度封顶、防重提交
  - **异常情况**：读取/写入/删除失败、AI 失败与冷却、知识库检索失败、锁定拦截、并发变更（卡点被删）、脏数据字段类型、内部渲染异常、云同步失败

回归有效性约定：每个缺陷修复都做「还原源码 → 确认对应用例失败 → 恢复」的验证，确保用例真的能捕获该缺陷。
